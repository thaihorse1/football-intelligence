# v0.4A — Worldwide near-term fixture discovery

Soccer Football Info via RapidAPI supplies supplementary worldwide fixture discovery.
It does not participate in verification or reconciliation. Records are DISCOVERED
and UNVERIFIED. Existing football-data.org, OpenLigaDB and API-Football behavior
is unchanged. Absence from this provider is never cancellation or negative evidence.
Even complete collection means all provider pages were inspected, not that every
worldwide fixture exists in the provider's feed.

## Configuration and transport

Required environment variables (also required for cache-only runs):

```
RAPIDAPI_KEY=
SOCCER_FOOTBALL_INFO_HOST=soccer-football-info.p.rapidapi.com
```

Endpoint: `GET https://{host}/matches/day/basic/` with `d=YYYYMMDD`, `p=<page>`,
`l=en_US`, and `f=json`. Credentials are sent in RapidAPI headers, never query
parameters. An explicit `football-intelligence/0.4A` User-Agent avoids the rejection
seen with Python urllib's default User-Agent. Gzip Content-Encoding is explicitly
decoded; uncompressed JSON is also supported. Redirects are refused to protect
credentials and keep every network request within the budget. There are no retries.

Prior live testing (outside this implementation) verified HTTP 200, JSON, gzip,
the status/errors/pagination/result envelope, 25-result pages and pagination such
as `[{"page":1,"per_page":25,"items":1666}]`. Future worldwide NOT_STARTED
fixtures were present, but upcoming Bundesliga fixtures were absent from the
tested future daily feed. This absence must not be treated as negative evidence.
No live provider requests were performed for this implementation or its tests.

`provider_kickoff` centralizes the assumption that naive provider timestamps are
UTC, based on that prior testing. Explicit offsets are converted to UTC. Provider
calendar dates are therefore treated as UTC dates. Bangkok conversion uses
`Asia/Bangkok`.

**Verified BASIC payload mapping:** the mapping was confirmed from a previously
saved successful provider response from 2026-10-04. The adapter uses `id`, `date`,
`status`, `championship.{id,name}`, `teamA.{id,name}` for the home team, and
`teamB.{id,name}` for the away team. Country is unavailable in the tested BASIC
payload and is therefore null rather than inferred.

## Usage

```
python -m app.soccer_football_info_discovery \
  --from 2026-10-10T00:00:00Z --hours 24 --max-requests 40
python -m app.soccer_football_info_discovery \
  --from 2026-10-10T22:00:00+00:00 --hours 6 --max-requests 10 --refresh
```

These commands acquire provider data when cache entries are unavailable; they are
examples, not validation commands. Defaults are current UTC time, 24 hours and
40 requests. Start must have a timezone; hours must be positive and finite and
max-requests must be a positive integer. The window includes its start and excludes
its end. Every UTC date intersecting it is inspected, with no chronological page
skipping. Filtering happens after normalization. JSON is printed to stdout; fatal
errors exit 1 with a sanitized stderr message and no report.

The optional Compose `soccer-discovery` service uses the existing image, collectors
profile, non-root user, read-only root filesystem and security hardening, without
published ports. It mounts only the cache directory writable. Before using it,
create `data/cache/soccer_football_info` and make it writable by container UID 10001
using the deployment's normal ownership provisioning. Explicit CLI arguments can
be passed with `docker compose --profile collectors run --rm soccer-discovery
python -m app.soccer_football_info_discovery ...`.

## Cache, pagination and coverage

Raw decoded successful responses are stored at
`data/cache/soccer_football_info/YYYY-MM-DD/page-001.json`, etc. Existing .gitignore
rules exclude them. Cache writes use temporary files and atomic replacement.
Valid cache entries consume no request budget; invalid entries are reacquired.
`--refresh` bypasses existing entries and replaces them only on successful retrieval.
`--cache-dir` changes the root. There is no expiry policy, so cached status and
pagination may become stale; use refresh when freshness matters.

Every page validates envelope, integer pagination values, expected result length
and fixture shape. Page counts are derived from items/per_page, with one inspected
page even for an empty date. Changing pagination within a date fails the run rather
than claiming complete inspection. Missing credentials, transport errors, invalid
JSON, provider errors and malformed required scheduled-fixture fields are fatal.

Every network attempt consumes one budget unit; cache hits consume none. Budget
exhaustion alone returns valid partial JSON with `coverage.complete=false` and an
explicit reason. Subsequent dates can still reuse cached pages. Coverage contains
requested dates, per-date available/processed page counts and completeness, total
processed pages, network requests, cache hits and max_requests. Unknown page counts
are null. A zero-fixture complete report means no matching fixtures were found in
all inspected provider pages; a zero-fixture partial report leaves discovery open.
Completeness never claims authoritative worldwide coverage.

## Normalized records

Each record contains provider, fixture_id, competition_id, competition, country,
home_team_id, home_team, away_team_id, away_team, kickoff_utc, kickoff_bangkok,
status, provider_status, discovery_status and verification_status. Provider IDs
retain their original values. Country is unavailable in the tested BASIC payload and is therefore null
rather than inferred. NOT_STARTED maps to SCHEDULED; all other nonempty provider
states are explicitly excluded. Missing status is malformed. Identical normalized
duplicates collapse; conflicting normalized records with the same fixture ID fail,
even outside the requested window. Results are sorted by UTC kickoff.

The report includes provider, generated_at_utc (actual generation time),
window_start_utc, window_end_utc, total_fixtures, fixtures and coverage.

## Development decision

Development step: v0.4A — Worldwide near-term fixture discovery.

Decision: **ADAPT**.

Reason: Adopt established date-scoped ingestion, explicit pagination, local
caching, rate-budget awareness, and no-silent-truncation patterns while retaining
Soccer Football Info as a supplementary global-discovery provider.

Firecrawl remains outside v0.4A and will be evaluated before custom
web-acquisition/scraping infrastructure is built.
