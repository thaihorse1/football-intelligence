# v0.4B — Candidate Universe / Verification Handoff

v0.4B is an offline verification handoff. It reads saved normalized reports and
prints a candidate-universe JSON report. No API or network calls occur. SFI remains
the discovery anchor; this component does no betting intelligence, scraping, data
acquisition or automatic exclusion. Verifier absence is not cancellation evidence.

Only Bundesliga is mapped initially in `config/competition_registry.json`:
SFI ID `a0d28d6b99d45e79` and exact name `Bundesliga I`, football-data.org `BL1`,
OpenLigaDB `bl1`, and API-Football `BL1` / league ID 78. The SFI ID and name must
both agree with the registry. No competition-name fuzzy matching occurs. Other
competitions remain valid discovery candidates. Registry validation permits only
one Bundesliga entry and checks mapping field types and duplicate identities.

## Usage

```
python3 -m app.build_candidate_universe --discovery data/sfi-discovery.json
python3 -m app.build_candidate_universe \
  --discovery data/sfi-discovery.json \
  --football-data data/football_data_bl1.json \
  --openligadb data/openliga_fixtures.json \
  --api-football data/api_football_bl1.json \
  --competition-registry config/competition_registry.json
```

Discovery is required and must identify `soccer-football-info`. The other reports
are optional. Every report must have an ordered, timezone-aware start/end window
and a fixture list with source provenance, IDs, team names and aware kickoff times.
SFI observations also retain their normalized scheduled/discovery state and team
and competition IDs. Conflicting duplicate IDs are fatal; identical observations
collapse. Inputs are never mutated. Invalid JSON, report shape, timestamps or
registry contents produce a sanitized stderr error, exit 1, and no stdout report.

## Coverage and matching

Verifiers are processed in order: football-data.org, OpenLigaDB, API-Football.
For each discovery, coverage is:

- NOT_PROVIDED when no report was supplied.
- NOT_APPLICABLE when competition coverage is absent or the discovery kickoff
  is outside the supplied report's inclusive-start, exclusive-end window.
- INCOMPLETE when the mapped OpenLigaDB league has ERROR or a mapped supplied
  report explicitly declares incomplete coverage/failure.
- COMPLETE when the mapped report covers the fixture window and succeeds.

OpenLigaDB's current normalized observations omit league codes; fixture filtering
uses exact canonical competition name `Bundesliga`, while report coverage uses
`bl1`. Unrelated league errors do not invalidate Bundesliga coverage. Missing
mapped league coverage is NOT_APPLICABLE. API-Football uses competition code and,
when present, checks league ID as well. No supplied API-Football report, including
absence due to plan limitations, produces NOT_PROVIDED rather than negative evidence.

Only COMPLETE sources are searched. Observations must belong to the mapped
competition and fall within 24 hours of the anchor. Existing v0.3C helpers are
imported and reused: canonical_team, kickoff, kickoff_difference_minutes,
team_similarity, exact_team_match, KICKOFF_TOLERANCE_MINUTES and FUZZY_THRESHOLD.
The existing 15-minute tolerance and 0.78 fuzzy threshold apply. The legacy
reconcile() first-match behavior is not reused.

Home and away remain oriented; reversed canonical pairings are rejected. Exact
canonical matches take precedence: one exact candidate yields MATCH and multiple
exact candidates yield AMBIGUOUS, ignoring fuzzy alternatives entirely. Fuzzy
matching is evaluated only when no exact candidate exists; multiple accepted
fuzzy candidates remain AMBIGUOUS. The component never picks a highest-scoring
observation from multiple candidates in the selected matching tier.

No plausible observations yields NO_MATCH. One yields MATCH with provider ID,
CANONICAL_EXACT or FUZZY method, team similarity, kickoff difference, conflict list
and the complete original observation. More than one yields AMBIGUOUS, retaining
every plausible ID and full evidence without selecting a single observation.
Fuzzy differences alone are accepted; kickoff differences over 15 minutes attach
KICKOFF_CONFLICT. Exactly 24 hours is inside the search envelope.

## Candidate report

Candidate identity is `sfi:` plus the discovery fixture ID. Candidates preserve
both the display fixture and complete original discovery observation. Verifier
observations never replace the discovery anchor. Source-scoped matched conflicts
are retained separately at candidate level.

Any ambiguous source yields REVIEW / AMBIGUOUS, taking precedence over conflicts.
Otherwise a matched kickoff conflict yields REVIEW / CONFLICT. With no such issue,
zero clean matches yields ACTIVE / UNVERIFIED, one yields ACTIVE / VERIFIED, and
two or more independent sources yield ACTIVE / MULTI_SOURCE_VERIFIED. COMPLETE
NO_MATCH is recorded without exclusion or conflict. No numeric confidence score
is manufactured.

The envelope includes schema_version `0.4B`, actual generated_at_utc, total_candidates,
status summary and candidates. Discovery metadata includes coverage_complete, the
original coverage object and the original time window. Candidate counts describe
the supplied discovery, never a complete worldwide universe when discovery
coverage is incomplete. Candidates sort by kickoff instant and then candidate_id;
ambiguous observations have deterministic ordering as well.

## Development decision

Decision: **REUSE + ADAPT**.

REUSE: existing team canonicalization, aliases, similarity, kickoff comparison
and thresholds.

ADAPT: multi-source provenance and ambiguity-preservation philosophy.

NEW: minimal competition registry and discovery-centered verification handoff.
